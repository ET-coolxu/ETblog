# 阶段四：后台发文、图片上传与访问统计页

阶段 3 已经能搜、能订 RSS、能记 PV。阶段 4 把浏览器里的写稿接上：登录、改 `content/posts/` 里的 Markdown、插图、看统计。后台**不是**另一份文章数据库，只是这些文件的编辑器。

打开 `npm run dev` 后，建议按「登录失败 → 登录成功 → 新建草稿 → 访客不可见 → 发布且含图 → 再编辑前台更新」走一遍。用户名、密码来自 `.env.local` 的 `ADMIN_USER`（默认 `admin`）和 `ADMIN_PASSWORD`。

---

## 1. 和阶段三相比，多了什么

```
未登录访问 /admin/stats
  → proxy.ts 发现没有 admin_session cookie
  → 重定向 /admin/login

POST 登录表单
  → loginAction
       ├─ verifyAdminCredentials（笼统失败提示）
       └─ 种 httpOnly cookie（HMAC，7 天）

保存文章
  → createPostAction / updatePostAction
       ├─ savePost 写入 content/posts/{slug}.md
       └─ revalidatePath（首页、列表、正文、标签、搜索、RSS、sitemap）

拖拽/粘贴图片
  → POST /api/upload（须登录）
       └─ public/uploads/{yyyy}/{mm}/文件
          正文插入 ![图片](/uploads/...)；封面可写入封面框
```

统计页只读 `lib/stats.ts`，计数规则仍是阶段 3 的：访客打开已发布正文 +1，管理员 session 不记。

## 3. 登录怎么拦

两层，避免只靠界面藏链接：

1. **`proxy.ts`（乐观检查）**：请求到达页面之前看有没有 `admin_session` cookie。没有就去登录页；`/api/upload` 没有则 401。不在这里用密钥验签，避免把鉴权逻辑都堆在请求边界。
2. **`(dashboard)/layout.tsx` 和 Server Action / 上传接口**：调用 `hasAdminSession()`，用 `SESSION_SECRET` 验 HMAC 和过期时间。cookie 伪造或过期会失败。

密码错误只提示「用户名或密码不正确」，不区分是用户名错还是密码错。`ADMIN_PASSWORD` 或 `SESSION_SECRET` 为空时，登录直接失败。

登出：顶栏按钮走 `logoutAction`，也可以打开 `/admin/logout`。

## 4. 为什么保存后前台立刻能看见

公开页会把渲染结果缓存。后台写入磁盘后调用 `revalidatePath`，把首页、`/posts`、`/posts/{slug}`、标签、搜索、`/feed.xml`、`/sitemap.xml` 标为过期。下一次有人打开这些地址，会重新读 Markdown。

不要靠 `next build` 再发一篇文章。开发时改文件也会热更新；生产环境靠的就是这次 revalidate。

## 5. 图片规则

- 允许：png / jpg / jpeg / webp / gif
- 单文件最大 5MB
- 禁止 svg（扩展名、MIME、文件头都会拦）
- 目录：`public/uploads/{年}/{月}/`，文件名带时间戳，防止覆盖
- 失败时编辑器里显示原因（超限、类型不对、未登录）

封面可以是 frontmatter 里的站内路径（例如 `/uploads/2026/09/cover.webp`）或 `https://` 外链。编辑器可直接选图上传到封面框，也可手填；外链图依赖对方站点。正文插图的 alt 默认为「图片」，不要用原始文件名。

## 6. 建议自己试

1. 未登录打开 `/admin`、`/admin/stats`，应回到登录页。
2. 故意输错密码，只看到笼统提示。
3. 登录后新建一篇草稿（手填 slug，保存后文件名为 `{手填}-{序号}`），访客打开 `/posts/{最终 slug}` 为 404，列表里没有它。
4. 插入一张 png/webp，点发布，前台正文能看到图。
5. 再改标题保存，刷新前台标题已变。
6. 编辑页 slug 是只读的；没有删除按钮，也没有关于页编辑入口。
7. `/admin/stats` 能看到总 PV、分文 PV、热门 Top 10。
