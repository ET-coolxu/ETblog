# 阶段二：对着本仓库学公开阅读

阶段 1 解决了「框架怎么把文件变成页面」。阶段 2 解决的是：**文章不在 `app/` 里，运行时去读 `content/` 下的 Markdown，再渲染成公开站点。**

建议先读完 [01-阶段一-Next.js骨架.md](./01-阶段一-Next.js骨架.md) 的第 3–6 节（路由、layout、Server Component），再对照本文。打开 `npm run dev`，按「首页 → 文章 → 正文 → 标签 → 关于」点一遍。

本阶段**没有**做：搜索、RSS 真正输出、暗色模式、访问统计、后台。`/search` 和页脚 RSS 仍是占位。

---

## 1. 和阶段一相比，多了什么

外壳没换：还是 `app/layout.tsx` + `app/(site)/layout.tsx`（导航 / 页脚）。变的是「`(site)` 下面有了一批真正的 `page.tsx`」，以及两个核心库。

```
请求 /posts/first-notes
  → RootLayout
    → SiteLayout（页眉页脚）
      → PostPage  app/(site)/posts/[slug]/page.tsx
           ├─ getPublishedPost("first-notes")   lib/posts.ts
           │     读 content/posts/first-notes.md
           ├─ renderMarkdown(body)              lib/markdown.ts
           └─ TableOfContents                   客户端组件，跟滚动高亮
```

关键决策（和 PRD 一致）：**Markdown 是唯一信源。** 不要用 `@next/mdx` 把 `.md` 放进 `app/`。那样发一篇新文章就要改路由、甚至重新 build；现在只要往 `content/posts/` 丢文件（开发时热更新，生产靠阶段 4 的 `revalidatePath`）。

## 3. 文章文件长什么样

打开 `content/posts/first-notes.md`。上半是 YAML **frontmatter**（`---` 包起来），下半是正文：

```yaml
---
title: 先把笔记写下来
date: 2026-08-26
tags:
  - 笔记
  - Markdown
summary: ...
cover: /uploads/2026/08/cover-notes.svg
featured: true
---
```

| 字段 | 规则（见 `lib/posts.ts` 的 `toMeta`） |
|---|---|
| `title`、`date` | 必填；缺了这篇会被丢掉，不当文章 |
| `date` | `YYYY-MM-DD`。YAML 有时会把它解析成 `Date`，代码里两种都收 |
| `tags` | 字符串数组，可空 |
| `summary` | 空则截正文纯文本约 120 字 |
| `cover` | 必须是站内路径，以 `/` 开头，拒绝 `//` 和 `://` |
| `draft` | 只有显式 `true` 才算草稿；缺省当已发布 |
| `featured` | 只有显式 `true` 才上首页精选 |

**文件名 = slug。** `first-notes.md` 的网址是 `/posts/first-notes`。slug 只允许 `[a-z0-9-]+`。

草稿示例 `unfinished-draft.md` 写了 `draft: true`。列表、标签、首页都看不到它；打开 `/posts/unfinished-draft` 是 404。

封面文件在 `public/uploads/2026/08/`。`public/` 下的东西按原路径对外：`/uploads/2026/08/cover-notes.svg`。

## 4. `lib/posts.ts`：运行时读磁盘

这是阶段 2 的数据层。页面不直接 `fs.readFile`，都走这里。

### 4.1 路径从哪来

```8:9:lib/posts.ts
const POSTS_DIR = path.join(process.cwd(), "content", "posts");
const ABOUT_FILE = path.join(process.cwd(), "content", "pages", "about.md");
```

`process.cwd()` 是 Node 进程的工作目录，本地 `npm run dev` 时就是仓库根。Docker 里是容器的 `/app`，和 compose 挂载的 `./content` 对上。

这是**服务端**代码。浏览器拿不到 `fs`。所以调用它的页面必须是 Server Component（不要加 `"use client"`）。

### 4.2 防路径穿越

即使用户传入 `../../etc/passwd` 这种 slug，也不能读出 `content/posts` 以外的文件：

```35:47:lib/posts.ts
function resolvePostFile(slug: string): string | null {
  if (!isValidSlug(slug)) {
    return null;
  }

  const filePath = path.resolve(POSTS_DIR, `${slug}.md`);
  const relative = path.relative(POSTS_DIR, filePath);
  if (relative.startsWith("..") || path.isAbsolute(relative)) {
    return null;
  }

  return filePath;
}
```

先用正则卡死 slug，再用 `path.relative` 确认解析后的路径仍在目录内。非法 slug 直接当「没有这篇文章」。

### 4.3 gray-matter：切开头信息和正文

```164:165:lib/posts.ts
  const parsed = matter(raw);
  const meta = toMeta(slug, parsed.data, parsed.content);
```

`parsed.data` 是 frontmatter 对象，`parsed.content` 是 Markdown 正文。`toMeta` 把未知类型收成 `PostMeta`；缺 `title`/`date` 返回 `null`。

### 4.4 草稿对访客不可见

对外 API 都不返回草稿：

- `listPublishedPosts()`：列表 / 首页 / 标签用，`.filter((post) => !post.draft)`
- `getPublishedPost(slug)`：草稿或读失败都返回 `null`，页面再 `notFound()`
- `getAdjacentPosts`：只在已发布列表里找上一篇 / 下一篇（列表已按日期降序）

内部 `readPostFile` 仍带 `draft` 字段，只是不导出给页面。阶段 4 后台会需要看草稿，那时再加「含草稿」的函数，不要把过滤逻辑拆到每个 `page.tsx` 里。

### 4.5 `cache()`：同一请求里别读两遍盘

```208:208:lib/posts.ts
export const listPublishedPosts = cache(async (): Promise<PostMeta[]> => {
```

`generateMetadata` 和页面组件常常会各调一次 `getPublishedPost`。`React.cache` 让**同一次渲染**里相同参数只执行一次。这不是跨请求的 Redis，刷新页面仍会再读文件。开发时改 `.md` 能看到更新，就是因为每次请求重新读盘。

关于页：`getAboutSource()` 文件不存在就返回 `null`，页面显示「尚未填写关于页」，不抛错、不 500。

## 5. 动态路由、searchParams、`notFound()`

Next 16 里 `params` 和 `searchParams` 都是 **Promise**，页面里要 `await`。这和很多旧教程里的同步 props 不一样。

### 5.1 动态段：`[slug]`

```13:34:app/(site)/posts/[slug]/page.tsx
type PostPageProps = {
  params: Promise<{ slug: string }>;
};

export default async function PostPage({ params }: PostPageProps) {
  const { slug } = await params;
  const post = await getPublishedPost(slug);
  if (!post) {
    notFound();
  }
```

`notFound()` 会立刻停掉当前渲染，改走最近的 `not-found.tsx`：

- `(site)/not-found.tsx`：公开站 404，外面已有 site layout（有导航）
- 根上 `app/not-found.tsx`：没有 site layout 的路由用，所以自己又写了一次 Header/Footer

草稿和未知 slug 都走这条路，访客看到的是同一句「没有找到」，不会泄露「这篇是草稿」。

标签页 `[tag]` 要 `decodeURIComponent`，因为中文标签在 URL 里是编码过的。`tagHref("笔记")` 会生成 `/tags/%E7%AC%94%E8%AE%B0`。无匹配时本实现用空状态，不 404。

### 5.2 查询串：`?tag=` 和 `?page=`

`/posts` 不是动态文件夹，筛选靠 URL 查询参数：

```9:25:app/(site)/posts/page.tsx
type PostsPageProps = {
  searchParams: Promise<{ tag?: string; page?: string }>;
};

export default async function PostsPage({ searchParams }: PostsPageProps) {
  const { tag, page: pageParam } = await searchParams;
```

`lib/posts.ts` 的 `postsHref({ page, tag })` 负责拼链接，分页组件只消费它。每页 10 篇；页码非法或过大时会钳到合法范围。

### 5.3 页面可以是 `async`

阶段 1 首页是同步函数。阶段 2 改成：

```4:7:app/(site)/page.tsx
export default async function HomePage() {
  const site = getSiteConfig();
  const posts = await listPublishedPosts();
```

Server Component 允许 `async`，在服务器 `await` 完再输出 HTML。不要在客户端组件里直接 `await` 读文件。

首页规则：先列出 `featured: true`；「最新」最多 6 篇，且不含已出现在精选里的，避免同一篇出现两次。

### 5.4 每页自己的标题

根 layout 的 template 仍是 `%s · {SITE_NAME}`。子页补 `title`：

```ts
export const metadata: Metadata = { title: "标签" };
```

或按数据生成：

```13:19:app/(site)/posts/[slug]/page.tsx
export async function generateMetadata({
  params,
}: PostPageProps): Promise<Metadata> {
  const { slug } = await params;
  const post = await getPublishedPost(slug);
  if (!post) {
    return { title: "未找到" };
  }

  return { title: post.title };
}
```

打开 `/posts/first-notes`，浏览器标签应是「先把笔记写下来 · 个人博客」（站名以你的 `.env.local` 为准）。

## 6. `lib/markdown.ts`：Markdown 变成 React，但不是 JSX 文章

`renderMarkdown` 用 `next-mdx-remote/rsc` 的 `compileMDX`，同时写死了：

```63:64:lib/markdown.ts
        format: "md",
        remarkPlugins: [remarkGfm],
```

`format: "md"` 表示按 **Markdown** 编译，不是 MDX。正文里写 `<SomeComponent />` 或原始 HTML **不会**当 React 跑。这是产品约束，不是漏了功能。

插件链：

| 插件 | 作用 |
|---|---|
| `remark-gfm` | 表格、任务列表、删除线、裸链接 |
| `rehype-slug` | 给 h2/h3 加 `id`，才能 `#锚点` |
| `rehype-autolink-headings` | 标题可点，class 为 `heading-anchor` |
| `@shikijs/rehype` | 代码块高亮，主题 `vitesse-light` |

唯一换成自定义组件的是 `img` → `MarkdownImage`：拒绝 `javascript:` / `data:` 地址。配图没有固定宽高，所以不用 `next/image`。

正文样式不靠 Tailwind 工具类堆出来，而是包一层 `className="markdown"`，规则写在 `app/globals.css` 的 `.markdown ...`。目录高亮、任务列表、代码横滑都在那里。

`next.config.ts` 多了：

```5:5:next.config.ts
  serverExternalPackages: ["shiki", "@shikijs/rehype"],
```

Shiki 要在运行时加载语法包，不要被打包器打成浏览器 bundle。这只影响服务器。

## 7. 第一次认真碰到 `"use client"`

阶段 1 可以全是 Server Component。阶段 2 有两处必须在浏览器跑：

### 7.1 `SiteNav`：当前栏高亮

```1:4:components/site-nav.tsx
"use client";

import Link from "next/link";
import { usePathname } from "next/navigation";
```

`usePathname()` 是客户端 Hook，会随路由变。`SiteHeader` 本身仍是服务器组件：它读 `SITE_NAME`，再把 `<SiteNav />` 嵌进去。这是推荐拆法——**能留在服务端的留下，只有要交互的那一小块标 client。**

`"use client"` 写在文件**第一行**。它不是「这个函数是客户端」，而是「这个模块以及它 import 的后续组件都进入客户端包」。所以不要把 `lib/posts.ts` import 进 client 文件。

### 7.2 `TableOfContents`：滚动高亮 + 移动端折叠

服务端先算好目录（纯文本，可序列化），再传给客户端：

```36:40:app/(site)/posts/[slug]/page.tsx
  const [content, adjacent] = await Promise.all([
    renderMarkdown(post.body),
    getAdjacentPosts(post.slug),
  ]);
  const toc = extractToc(post.body);
```

`extractToc` 用 `remark` 再解析一遍 Markdown，只收集 h2/h3，id 用 `github-slugger` 生成，和 `rehype-slug` 同一套算法，才能对上标题的 `id`。

客户端用 `IntersectionObserver` 看哪个标题进入视口上半，更新 `activeId`。桌面：`lg:block` 的 sticky 侧栏；手机：`<details>` 折叠。没有标题就 `return null`。

**不能**把 `renderMarkdown` 放到这个 client 组件里：高亮很重，而且会把 Shiki 打进浏览器。数据在服务器算完，UI 状态在客户端，这是阶段 2 最值得记住的组合。

`Promise.all` 让「渲染正文」和「找相邻文章」并行，不必串行等待。

## 8. 示例数据怎么对应页面

仓库里三篇 + 关于页，专门方便你对照行为：

| 文件 | 你会在哪看到 |
|---|---|
| `first-notes.md`（`featured`，有封面、代码、表格） | 首页精选；`/posts/first-notes` 可试目录和高亮 |
| `reading-markdown.md`（GFM：任务列表、删除线、引用） | 首页最新；和上一篇互为「上一篇 / 下一篇」 |
| `unfinished-draft.md` | 任何公开列表都没有；`/posts/unfinished-draft` → 404 |
| `pages/about.md` | `/about` |

日期：草稿是 08-28（最新），但因为是草稿，不能当「下一篇」。已发布两篇里，08-27 的 `reading-markdown` 更新，08-26 的 `first-notes` 更旧。阅读页上「上一篇」是更旧，「下一篇」是更新。

## 9. 建议亲手做的实验

1. **改一篇已发布正文**  
   编辑 `content/posts/first-notes.md` 某一段，保存，刷新 `/posts/first-notes`。开发模式会重新读文件，不必重启。

2. **把草稿公开**  
   去掉（或改成 `false`）`unfinished-draft.md` 的 `draft: true`，看它是否出现在首页 / 列表。做完改回去，避免以后验收乱掉。

3. **故意写坏 slug**  
   把某文件改名为 `Hello World.md` 或 `../oops.md`。`isValidSlug` 不会收它，公开站当它不存在。

4. **加一个动态页的直觉**  
   看清：`app/(site)/posts/[slug]/page.tsx` 只有一份，却能打开两篇已发布。新文章 = 新 md 文件，不是新 `page.tsx`。

5. **暂时拿掉关于页**  
   把 `content/pages/about.md` 改名，打开 `/about`，应看到空状态而不是报错。改回文件名。

6. **感受 client 边界（选做）**  
   在 `table-of-contents.tsx` 里 `import { listPublishedPosts } from "@/lib/posts"`，保存后看终端报错。原因：client 模块不能用 Node `fs`。删掉这行。
