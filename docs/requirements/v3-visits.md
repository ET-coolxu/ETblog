# 访问记录

本文取代 [后台工作台 V2](v2-admin.md) 里 `/admin/stats` 的页顶说明和「KPI 只有三格」，以及该文「不做」中的两处：

- 「分页」：只放开统计页的访问记录表。文章列表、热门文章、各篇文章和其他后台列表仍然不分页。
- 「只把已发布正文算进浏览次数」：总浏览和今日浏览的计入对象不变。另加访问记录和按 IP 去重的独立访客，范围包括首页、文章列表、已发布正文和关于。

没写到的行为仍按 V2，以及 V2 尚未取代的 [v1](v1.md)。谁计入 PV、删文时删除 `post_views` 行、存档不删 PV、管理员 session 不记，仍以 v1 第 7、8 节和 V2 的今日浏览为准。

## `/admin/stats`

保留现有三块，数字为 0 时仍显示 0：

- 总浏览：`post_views` 合计。删文后该 slug 的累计从总数去掉。
- 已发布篇数：状态为已发布的文章数。
- 今日浏览：`Asia/Shanghai` 自然日、访客成功打开已发布正文的次数。管理员 session 不记。删文不回退当日已发生的次数。

「热门文章」和「各篇文章」的列、排序、空状态、标题链到编辑页，保持 V2。

新增两格，放在现有 KPI 旁。上线前的访问无法回填，从这次部署之后开始计：

- 今日独立访客：上海时区当天，访问记录里不重复的 IP 数。
- 累计独立访客：访问记录里不重复的 IP 数。

同一 IP 刷新多次，访问记录有多行，独立访客只算 1。过了上海时区零点后，今日独立访客按新的一天重计，累计独立访客不回退。

页顶说明同时覆盖两套数字：总浏览和今日浏览仍是已发布正文；独立访客和访问记录还包括首页、文章列表和关于。管理员访问不计入。无图表。

## 访问记录

记这些公开页，且页面成功打开之后才记。Next 的路由预取和浏览器 prefetch 不算打开。带管理员 session 不记。失败只打日志，不抛给访客，也不新增公开的统计接口。

- `/`：首页
- `/posts`：文章列表。含翻页 `?page=`。`?tag=` 是标签筛选，不记。
- `/posts/[slug]`：仅已发布正文。草稿、存档、不存在的 slug 不记，与 `recordPostView` 的条件一致。这一次打开仍给 `post_views` 和 `daily_views` 加 1，并同时写一行访问记录。
- `/about`：关于。正文还没写、页面仍能打开时也记。

`/tags`、`/tags/[tag]`、搜索页、后台页面不记。首页、文章列表、关于只写访问记录，不加进总浏览和今日浏览。

每条记录保存：时间、页面、完整 IP、来源。来源为空时显示「直接访问」。来源超过 512 个字符时截断后再存。时间按上海时区显示到分钟。

页面列：首页、文章列表、关于用这三个中文名；正文用文章标题，标题链到该文编辑页。文章后来被删了，这一行仍保留，页面列改为当时的路径，不要链接。删文不删除、不改写已有访问记录，也不改 `post_views` 的主键语义。新记录用新表，仍在应用内 SQLite（`data/stats.sqlite`）。

IP 显示完整地址，IPv4 和 IPv6 都要能存。只出现在已登录的统计页，不出现在公开页面、RSS 或接口响应里。生产环境经 Caddy 反代，且未配置 `trusted_proxies`：Caddy 忽略客户端自带的 `X-Forwarded-For`，改写成它看到的连接地址，应用使用这个地址。本机直接访问、请求里没有该头时，用连接上的地址。

统计页在现有表格下方加「访问记录」。列：时间、页面、IP、来源。按时间从新到旧。每页 20 条，用上一页 / 下一页翻更早的记录，页码留在查询参数里，刷新后仍停在当前页。没有记录时用中文空状态，不显示分页。只有一页时不给出翻页。

## 本期不做

识别爬虫，地图，图表，导出，访客轨迹，User-Agent 解析，回填上线前的访问，公开统计接口，删文时改写访问记录，以及其他后台列表的分页、搜索、多选、批量。不引入 Umami、Postgres 或其他统计服务。
