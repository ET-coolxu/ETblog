# 项目架构

ET blog。做哪一版以用户说出的「现在开始做 V…」为准，文档在 [`docs/requirements/`](../requirements/)。该版写明取代的条目以它为准，没写到的行为仍看更早且未被取代的需求。

## 技术栈

Next.js App Router + TypeScript，`output: 'standalone'`。本地用 Node.js 20+ 跑 `npm run dev`。生产镜像由 GitHub Actions 在 `main` 推到 `ghcr.io/et-coolxu/etblog`，VPS 只 pull，不在服务器上 `next build`。

## 目录

```text
app/                  页面与路由。公开站在 app/(site)/，后台在 app/admin/
components/           可复用界面
lib/                  文章读写、搜索、统计、鉴权
proxy.ts              后台与上传的 cookie 拦截
content/              Markdown 信源（posts、pages）
public/uploads/       文章图片
data/                 SQLite
mcp/coolxu-blog/      调用 Publish API 的 MCP 客户端
docs/requirements/    产品需求
docs/架构/            本说明
docs/agent/           提示词类型模板与已确认提示词
docs/agent-prompts/   旧任务提示词，只作历史记录
docs/项目说明/        分阶段实现笔记
.cursor/rules/        协作规则
.github/workflows/    test 上构建校验；main 推镜像并部署
scripts/              VPS 拉镜像
```

## 约束

- Markdown 是唯一信源：`content/posts/{slug}.md`、`content/pages/about.md`。不另存文章数据库
- slug 仅 `[a-z0-9-]+`，创建后不可改；读写防路径穿越
- 图片放在 `public/uploads/{yyyy}/{mm}/`。发布后 `revalidatePath`，不整站重建
- 站名和作者来自 `getSiteConfig()`，不写死
- 单管理员 session；搜索用服务端 Flexsearch；统计用应用内 SQLite
- 功能先合入 `test` 看构建，再生产只跟 `main` 的 GHCR 镜像

## 协作规则

| 规则 | 何时生效 | 约束什么 |
| --- | --- | --- |
| `.cursor/rules/project.mdc` | 每次对话 | 范围、文档依据、工程约定 |
| `.cursor/rules/iteration.mdc` | 每次对话 | 需求换版时同步改规则和说明 |
| `.cursor/rules/agent-prompts.mdc` | 每次对话 | 未要求实现时只整理提示词 |
| `.cursor/rules/app.mdc` | 编辑站点应用文件 | 页面放哪、服务端边界、样式 |
| `.cursor/rules/mcp.mdc` | 编辑 MCP 客户端 | 只转发 Publish API，不写本地文章 |
