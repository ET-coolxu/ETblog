# 栏宽

公开站的水平文字栏只有一组变量：`--measure`、`--toc`、`--toc-gap`、`--gutter`，定义在 `app/styles/tokens.css`。普通页用 `app/styles/shared.css` 的 `.measure`。文章页用 `components/table-of-contents` 的三列网格，中间列与 `.measure` 共用 `--measure` 和 `--gutter`。

这套架构只管公开站的水平文字栏。下面这些不进这四个变量：

- 后台侧栏、编辑器双栏
- 组件内部的 640px 排列：页脚横排、首页「最新」、列表缩略图、导航上的「搜索」二字、文章页相邻文章横排

`body` 字号是 `--text-base`（1rem），`html` 不另设字号。根字号 16px 时，52rem = 832px。

## 变量

| 变量 | 当前值 | 作用 |
| --- | --- | --- |
| `--measure` | 52rem | 文字栏上限 |
| `--toc` | 12rem | 宽屏目录本身的宽度 |
| `--toc-gap` | `var(--space-8)`，即 2rem | 目录和正文之间的间隔 |
| `--gutter` | `clamp(var(--space-5), 4vw, var(--space-10))`，即 `clamp(1.25rem, 4vw, 2.5rem)` | 文字栏两侧留白 |

`--toc` 加 `--toc-gap` 是 14rem。目录断点用这个和，不把 `--gutter` 算进去。`--toc-gap` 目前指向间距变量 `--space-8`；改间隔时改 `--toc-gap` 的值。断点字面量按解析后的长度写，不会跟着变量名自动变。

## 普通页

`.measure` 的宽度就是文字栏本身：

```css
width: min(var(--measure), 100% - var(--gutter) * 2);
margin-inline: auto;
```

视口装得下 52rem 加两侧留白时，栏宽停在 52rem，多出来的空间在栏外。装不下时，栏宽让出两份 `--gutter`。套了 `.measure` 的页面不再另加 `padding-inline` 或 `max-width`。

`.page` 和 `.page-tall` 只留上下 padding，水平宽度交给同一元素上的 `.measure`。

| 类 | 上下留白 | 谁用 |
| --- | --- | --- |
| `.page` | `var(--space-16)`（4rem） | 标签总览、搜索 |
| `.page-tall` | `var(--space-24)`（6rem） | 未找到页：`app/not-found.tsx`、`app/(site)/not-found.tsx` |

套 `.measure` 的还有顶栏内层、页脚内层、首页、文章列表（`/posts` 与 `/tags/[tag]`）、关于。首页、关于和文章列表的上下留白写在各自的类上，不走 `.page`。顶栏和页脚外层拉满，内层用 `.measure`，宽屏时与正文栏对齐。

文章页不套 `.measure`。

## 文章页

文章页 `main` 是 `width: 100%`，只有上下 padding。水平宽度由 `PostReadingFrame` 的三列网格决定，铺满这一层：

```css
grid-template-columns:
  minmax(var(--gutter), 1fr)
  min(var(--measure), 100% - var(--gutter) * 2)
  minmax(var(--gutter), 1fr);
```

第 2 列的宽度公式与 `.measure` 相同。正文在 `.column` 上钉死 `grid-column: 2`，并清掉自身的 `max-width` 和水平 margin。没有目录时左侧不渲染目录，正文仍在第 2 列。

视口达到目录断点时，目录出现在第 1 列，贴右、`sticky`。断点算式：

```text
--measure + 2 × (--toc + --toc-gap)
= 52rem + 2 × (12rem + 2rem)
= 52rem + 2 × 14rem
= 80rem
```

媒体查询不能写自定义属性。`80rem` 在 `components/table-of-contents.module.css` 写成 `@media (min-width: 80rem)`。改 `--measure`、`--toc` 或 `--toc-gap` 时，按同一算式改这个字面量，并改 `tokens.css` 注释里的同一行算式。

窄于 80rem 时，目录是标题和正文之间的 `<details>`（`TocDetails`）。到达 80rem 后这块隐藏，左侧栏接管。

全局 `box-sizing` 是 `border-box`。宽屏目录改回 `content-box`，12rem 才是目录本身，右侧 2rem 间隔在宽度之外。视口刚到 80rem 时，滚动条会让第 1 列略窄于 14rem，目录用 `max-width: calc(100% - var(--toc-gap))` 收进格子。这两句只说明滚动条下为什么收得住。

## 维护

新的公开页只用 `measure`。模块样式里不再用 `max-width` 或 `padding-inline` 收栏。文章阅读栏只用 `table-of-contents` 的网格。后台不引用这四个变量。

改 `--measure`、`--toc`、`--toc-gap` 时，按上面的算式改 `table-of-contents.module.css` 里的断点字面量，并同步本文、`docs/架构/项目架构.md` 和 `.cursor/rules/app.mdc` 里写死的数字（当前是 52rem 与 80rem）。只改 `--gutter` 时不用改 80rem。
