## 目标

- 把上述生产值写进 TODO / README 上线步骤，本地 `.env.example` 仍服务开发，不要把生产密码写进 Git。
- 新增 **`docs/vps-go-live.md`**：给**自动化运维助手**读的逐步操作清单（精确命令、成功标准、失败即停、禁止项）。操作员 AI 只执行该文件，不改应用代码、不改 `content/`。
- 根 README 增加「VPS 上线」入口，并指向该清单。
- 给出全新 VPS 从零到 HTTPS 的操作顺序：装 Docker → 拿公网 IP → DNS → 拉代码 → `.env` → 权限 → Compose → 验收。
- 生产只开放 80/443（及 SSH）；应用 3000 不映射到公网。
- Caddy 用 HTTP-01 自动签发 Let's Encrypt；`SITE_DOMAIN=coolxu.com`，`CADDY_EMAIL` 必须是邮箱。

## 非目标

- 不改文章、关于页、首页简介。
- 不做 www 跳转、CDN、Cloudflare 橙色云朵、独立监控、自动备份脚本（备份只在 README 里用一句话提醒）。
- 不改 Caddyfile 结构，除非验收证明当前变量替换无法用 `coolxu.com` 签发证书。
- 不提交 `.env`、密码、`SESSION_SECRET`。

## 决策

| 决策 | 选择 | 不选 |
|---|---|---|
| 规范主机名 | 只上线 apex `coolxu.com` | 暂不上 `www.coolxu.com` |
| DNS | 先解析再起带域名的 Caddy | 先起 Caddy 再解析（证书会失败） |
| Cloudflare 等代理 | 关闭（仅 DNS / 灰云）直到证书成功 | 第一版上 CDN |
| 生产环境变量 | 只存在 VPS 的 `.env` | 写进 `.env.example` 或提交 Git |
| 本地 Compose | 继续 `SITE_DOMAIN=:80` | 本机假装签发 `coolxu.com` |

## 约束

- 文章仍以 Markdown 为唯一信源；数据卷继续挂 `content/`、`public/uploads/`、`data/`。
- `SITE_URL` 必须是 `https://coolxu.com`（无尾斜杠）：sitemap、OG、管理员 cookie `Secure` 都靠它。
- `SITE_NAME="CoolXu's Blog"` 必须带双引号，否则撇号会截断。
- `CADDY_EMAIL` 必须是邮箱，不能填域名。
- 容器内 Next 用户 uid `1001`；`content/`、`public/uploads/`、`data/` 需可被该用户读写。
- 界面文案中文；站名/作者仍走环境变量，不要写死进组件。

## 验证

操作者在 VPS 上按下列清单执行；AI 不要在本机跑 `docker compose` / `next build`。

### A. 云面板（证书签发前必须做完）

1. 记下 VPS 公网 IPv4。
2. 安全组/防火墙放行 **22、80、443**；不要放行 3000。
3. 域名 DNS：`coolxu.com` 的 **A 记录**指向该 IPv4。不要随便加 AAAA（除非确认 VPS 有可用 IPv6）。不要开 Cloudflare 代理。
4. 本机确认：`nslookup coolxu.com`（或 `dig`）已返回该 IP。未生效不要起生产 Caddy。

### B. 全新 Ubuntu 服务器

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl git
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"
```

重新登录 SSH 后再检查 `docker compose version`。内存约 1GB 时建议加 2GB swap，否则 `docker compose build` 容易被杀。

### C. 代码与生产 `.env`

把 GitHub 上含阶段 1–4 的分支拉到 VPS（仓库若私有，先配 SSH deploy key 或 HTTPS token）。不要把本机 `.env` 提交进 Git。

```bash
git clone https://github.com/ET-coolxu/ETblog.git
cd ETblog
# 检出已推送的目标分支，例如 main 或 dev
cp .env.example .env
```

编辑 `.env`（仅 VPS，勿提交）：

```bash
SITE_NAME="CoolXu's Blog"
AUTHOR_NAME=coolxu
SITE_URL=https://coolxu.com
ADMIN_USER=admin
ADMIN_PASSWORD=（自定强密码，不要用示例里的值）
SESSION_SECRET=（在服务器上执行 openssl rand -hex 32）
SITE_DOMAIN=coolxu.com
CADDY_EMAIL=maxxubuly@gmail.com
```

```bash
sudo chown -R 1001:1001 content public/uploads data
```

### D. 启动与验收

```bash
docker compose up --build -d
docker compose logs -f caddy
```

日志里应出现证书申请成功，而不是 DNS / TLS 错误。然后：

- 浏览器打开 `https://coolxu.com`：标题与页脚为 CoolXu's Blog / coolxu；HTTP 应跳到 HTTPS。
- 打开一篇已发布文章、搜索、`/feed.xml`、`/sitemap.xml`（sitemap 里应是 `https://coolxu.com/...`）。
- `/admin` 用生产密码登录；访客打开草稿仍 404。
- 管理员访问不记 PV；无管理员 session 的正文记 PV。

失败时先看：DNS 是否已指向本机、80/443 是否通、`CADDY_EMAIL` 是否为邮箱、`SITE_URL` 是否 https、目录是否 uid 1001。
