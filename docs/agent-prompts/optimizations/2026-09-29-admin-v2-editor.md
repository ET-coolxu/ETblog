# 后台 V2 编辑器工作面

请按本提示词改编辑器布局。先读 `docs/requirements/v2-admin.md` 的「编辑器」、`components/post-editor.tsx` 与新建/编辑页。状态机、上传、预览管线保持现状。壳应已是侧栏。

## 背景

编辑器现在是上半截纵排文稿字段，下半截 Markdown 与预览。操作钮在表单最底。原型把操作收到顶栏，文稿信息放到左侧可收起栏，右侧才是写作与预览。原型只画了已发布文章的四颗按钮，不能据此让新建页也出现存档和删除。

## 目标

- 新建与编辑都变成：顶栏 + 左文稿栏 + 右 Markdown | 预览。
- 顶栏标题跟随表单标题；按钮集合仍按 v1：新建/草稿、已发布、已存档三套。
- 「收起 / 展开」只隐藏文稿栏。刷新后默认展开。
- 封面预览、外链失败说明、拖拽与粘贴插图、slug 只读与首次保存加序号，全部保留。

## 非目标

- 不改保存 intent、确认文案、删除后回 `/admin`、404。
- 不换成富文本，不在预览里渲染原始 HTML 以外的另一套 Markdown。
- 不把收起状态存进 localStorage。
- 不改 frontmatter 字段含义。`featured` 只改可见文案为「精选」。

## 约束

- 按钮显隐以服务端状态为准，不能只靠前端藏起来却仍接受非法 intent。现有 action 已校验的，保持。
- 存档与删除继续 `confirm`。
- 编辑器页在壳的主区里高度铺满：顶栏固定，文稿栏与预览各自滚动，Markdown 区域填满。整页不要再套一层长页面滚动把预览顶出视口。
- 宽度 &lt;1024px：文稿信息在上，Markdown 与预览上下排列。
- 危险「删除」使用 `--danger`（若壳未加令牌，在 `tokens.css` 补上：浅色 `#9b3b3b`，深色可读）。
- 预览区沿用现有 `.markdown` 输出，让标题呈衬线。不要在原型那段静态 HTML 上再写一套假预览。

## 验收标准

- [ ] 已发布文章的顶栏为：← 文章、标题、已发布 pill、保存、改为草稿、存档、删除
- [ ] 草稿与新建没有存档；已存档没有发布、也没有第二颗存档
- [ ] 新建 slug 可编辑；保存后的编辑页 slug 只读，并有「创建后不可改」
- [ ] 收起后再展开，未保存的表单内容还在
- [ ] 选择封面、粘贴图片、拖拽图片仍插入或写入封面；外链封面失败仍有中文说明
- [ ] 桌面预览与 Markdown 并排；窄于 1024px 改为上下
- [ ] 不存在的 slug 仍是后台 404

## 涉及范围

- 文件/模块：`components/post-editor.tsx`、`post-editor.module.css`；必要时 `app/admin/(dashboard)/posts/new/page.tsx`、`posts/[slug]/page.tsx` 与 dashboard layout 的高度传递
- 不影响：`posts/actions.ts` 的校验语义、上传接口白名单

## 实现要点

- 顶栏标题用已有的客户端 title state，空字符串显示「未命名」。状态 pill 用已保存状态，不随未提交的按钮预变。
- 「收起」是本组件 state。收起时字段仍在表单里（可视觉隐藏），提交不能丢 slug、正文和精选。
- 主按钮 pine 实心，次按钮描边，存档为弱文字按钮，删除在分隔线右侧。

## 验证

- 浏览器各走一遍：新建保存草稿、发布、已发布改为草稿、存档（看确认框）、存档改为草稿、删除（看确认框并回到列表）。
- 收起、改标题、刷新前不要提交，确认展开后字还在；刷新后栏是展开的。
- 上传一张封面、往正文粘贴一张图，预览里看得到。
- 桌面与 &lt;1024px 各看一次写作区。
