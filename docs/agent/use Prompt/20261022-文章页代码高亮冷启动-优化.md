## 本次优化

开发服务器刚启动后，第一次打开任意文章要大约 6 秒，下一篇立刻降到大约 400 毫秒。重启 `npm run dev` 后第一篇又变慢。耗时拆成两段：Next.js 约 1.2 秒，应用代码约 4.7 秒。

应用代码这 4.7 秒来自 `lib/markdown.ts` 的 `rehypeShiki`。配置只写了主题 `vitesse-light` 和 `defaultLanguage: "text"`，没有传 `langs`。`@shikijs/rehype` 因此调用 `getSingletonHighlighter` 时载入 Shiki 自带的全部语言语法，以及 Oniguruma 的 WebAssembly。文章里有没有代码块都会走这一步。高亮器留在当前 Node 进程里，所以同一轮进程里的后续文章是快的。

这次只缩短这段冷启动。开发模式下第一次编译 `app/(site)/posts/[slug]/page.tsx` 的大约 1.2 秒保留，不预热路由，不加启动脚本。

做法已经指定，直接改：

1. `renderMarkdown` 和 `renderMarkdownPreviewHtml` 共用同一份 Shiki 配置，避免两处各初始化一次，或因为配置不一致而重建高亮器。
2. 给 `rehypeShiki` 传入有限的 `langs`，不要依赖「未传则加载全部语言」的默认值。初始集合用博客会写到的常见语言：`typescript`、`tsx`、`javascript`、`jsx`、`bash`、`shell`、`json`、`css`、`html`、`markdown`、`yaml`、`python`、`sql`、`diff`。
3. 打开 `lazy: true`。文章里出现初始集合之外的语言时，只在那一次请求里按需加载该语言。加载失败时用 `fallbackLanguage: "text"`，页面仍返回正文，不抛错。
4. 主题保持 `vitesse-light`，无语言标记的代码块保持 `defaultLanguage: "text"`。
5. 继续使用现有的 `@shikijs/rehype` 入口。不要改成 `shiki/core` 细粒度打包，也不要换高亮库。

## 前置约束

- 先澄清假设，不臆造需求
- 改动范围最小化；不重构无关代码
- 遵循 `.cursor/rules` 与 `docs/架构/项目架构.md`。产品行为以用户本次说的「现在开始做 V…」为准，文档在 `docs/requirements/`；没说明时先问

- 对外行为保持不变，除非本次说明明确要求改变

- slug 仅 `[a-z0-9-]+`，创建后不可改；读写防路径穿越
- 图片放在 `public/uploads/{yyyy}/{mm}/`。发布后 `revalidatePath`，不整站重建
- 站名和作者来自 `getSiteConfig()`，不写死
- 单管理员 session；搜索用服务端 Flexsearch；统计用应用内 SQLite
- 功能先合入 `test` 看构建，再生产只跟 `main` 的 GHCR 镜像
