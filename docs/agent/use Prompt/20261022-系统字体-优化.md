## 本次优化

按 `docs/字体方案-A-系统字体.md` 把全站字体改为系统字体。不要读 `docs/字体方案-B-自托管精简.md`，也不要按 `docs/coolxu-blog-font-typography-plan.md` 里的类名、色值或 720px 栏宽改代码。做法已经指定，直接改，不要再提供另一套字体方案。

现在全站只有 `--font-sans` 和 `--font-serif`。无衬线用于正文、导航、日期、标签和后台表单。衬线用于文章标题、正文 H2/H3、引用、列表标题、顶栏站名、关于页和后台大标题。这两个名字来自 `app/fonts/index.ts` 的 216 次 `localFont`（Inter、Newsreader、Noto Sans SC、Noto Serif SC 的 unicode-range 切片），经 `app/fonts/variables.css` 拼合后挂到 `body`。这套切片是为了绕过 Docker 里 `next/font/google` 的构建失败，页面不需要这些文件。

改完后不下载任何网页字体，构建期不访问 Google Fonts。删除切片、生成脚本和 `next/font` 加载。`--font-sans`、`--font-serif` 这两个名字保留。

`next/font` 去掉之后，把字体栈从 `body` 移回 `:root`，并删掉「字体栈必须写在 body 上」的注释。使用下面的字体名，不要添加 `@font-face` 或字体文件：

```css
--font-sans: "Segoe UI", "PingFang SC", "Hiragino Sans GB",
  "Microsoft YaHei", "Noto Sans CJK SC", sans-serif;
--font-serif: "Songti SC", "SimSun", "Noto Serif CJK SC", serif;
```

不要写成只有 `"Segoe UI", "Microsoft YaHei"`。`"Noto Sans CJK SC"` 和 `"Noto Serif CJK SC"` 只匹配设备上已经安装的字体。

各系统字形不同是预期结果：Windows 上中文无衬线是微软雅黑、衬线是宋体；macOS 上是苹方和宋体。不再有 Inter、Newsreader 和思源。雅黑没有 500/600 字重文件，这些字重由系统决定。不要为此再加字体文件。

具体改动：

1. `app/styles/tokens.css`：按上面的栈替换 `--font-sans`、`--font-serif`，并移到 `:root`。
2. `app/layout.tsx`：去掉 `fontVariableClassName` 的 import 和 `body` 上的 class。保留 `generateMetadata` 和 `ThemeProvider`。
3. `app/globals.css`：去掉 `@import "./fonts/variables.css"`。
4. 删除整个 `app/fonts/`。
5. 删除 `scripts/vendor-local-fonts.py`。确认没有别的脚本或 CI 步骤再调用它。

同一轮改掉仍把字体描述成 Google 切片的句子：

- `docs/requirements/v2-admin.md`：后台色板和字体仍跟访客站、仍用 `tokens.css`。删掉「现有 `next/font`」。继续不要引入另一套色值或 Source Sans 3。
- `docs/项目说明/01-阶段一-Next.js骨架.md` 第 6.2 节：改成系统字体栈，不再写 `next/font` 向 Google 拉字体。
- `docs/vps-go-live.md`：构建需要出网拉镜像，字体不再访问 `fonts.googleapis.com`。

若 README 或 `docs/架构/项目架构.md` 仍把当前字体写成 `next/font` 或 Google 切片，改成与本方案一致。`docs/存档/` 和 `.agents/skills/` 里的历史示例不要改。

组件里的 `font-family: var(--font-sans)`、`var(--font-serif)`、`font-optical-sizing`、`font-synthesis` 不动。系统字体没有光学尺寸轴时，浏览器忽略 `font-optical-sizing`。
