## 提示词正文

你是本仓库（ET blog）的架构助手。目标：把公开站的主体宽度收成一套可维护的栏宽。方案已经给定，按此核对并落地，不要另起一套断点或再引入工具类断点。默认到设计和文档段落为止；用户明确说「按这个实现」之后才改代码。

## 本次问题

公开站各页的水平宽度统一到同一条阅读栏，留白随视口连续变化，目录是否出现由这条栏宽算出来。后台保持现在的侧栏，不使用这套变量。

### 变量

全部放在 `app/styles/tokens.css` 的栏宽那一组，用 rem，好让根字号变化时栏宽和断点一起缩放。

```css
--measure: 40rem;
--toc: 12rem;
--toc-gap: var(--space-8);
--gutter: clamp(var(--space-5), 4vw, var(--space-10));
```

含义：

- `--measure` 是文字栏上限，40rem（根字号 16px 时为 640px）。文章正文 18px 时大约一行 36 字。
- `--toc` 是目录宽，12rem，替代现在的 `--toc-w: 190px`。
- `--toc-gap` 是目录和正文之间的间距，沿用 `--space-8`（2rem）。
- `--gutter` 是栏外的最小留白。窄屏 1.25rem，随视口增到最多 2.5rem，中间用 `4vw` 过渡。

删掉 `--column`、`--column-wide`、`--reading`、`--toc-w`。

在这四个变量旁边写一行注释，给出目录断点的算式，避免以后只改其中一个：

目录断点 = `--measure` + 2 × (`--toc` + `--toc-gap`) = 40rem + 2 × 14rem = 68rem。

媒体查询里不能写自定义属性，所以 `68rem` 要写成字面量。改 `--measure`、`--toc` 或 `--toc-gap` 时，按这个算式改 `components/table-of-contents.module.css` 里的那条媒体查询。

`tokens.css` 开头现在写的断点说明（sm 640、md 768、xl 1280、编辑器 1024）改成：公开站栏宽只有上面这组变量；640px 只用于组件内部的排列，不进入栏宽；编辑器 1024px 和后台 768px 不属于公开站栏宽。

### 普通页怎么限宽

`app/styles/shared.css` 只保留一条水平栏宽类，替换 `.shell`，以及 `.page`、`.page-wide`、`.page-tall` 上的 `max-width` 和左右 padding：

```css
.measure {
  width: min(var(--measure), 100% - var(--gutter) * 2);
  margin-inline: auto;
}
```

全局已经是 `border-box`。这条类的宽度就是文字栏本身，调用方不要再加 `padding-inline` 或 `max-width`，否则留白会叠两层。

`.page` 和 `.page-tall` 若仍被页面使用，只保留上下 padding（分别是现在的 `--space-16` 和 `--space-24`），不再管宽度。删掉 `.page-wide` 和 `--column-wide`，当前没有页面用它们。

使用处：

| 位置 | 现在 | 改为 |
| --- | --- | --- |
| `components/site-header.tsx` | `shell` | `measure` |
| `components/site-footer.tsx` | `shell` | `measure` |
| `app/(site)/page.tsx` | `shell py-12` | `measure py-12` |
| `components/post-index.tsx` | `shell` | `measure` |
| `app/(site)/tags/page.tsx` | `page` | `measure`，上下留白仍用只含纵向 padding 的类 |
| `app/(site)/search/page.tsx` | `page` | 与标签页相同 |
| `app/(site)/not-found.tsx`、`app/not-found.tsx` | `page-tall` | `measure`，上下留白仍用只含纵向 padding 的类 |
| `app/(site)/about/page.module.css` | 自己写 `max-width: var(--reading)`，正文再限 `40rem` | 根节点用 `measure`；删掉模块里的水平 `max-width` 和正文上的 `40rem`。上下留白留在该模块 |

顶栏本身仍是通栏固定，只有内部那一层用 `measure`，这样顶栏、页脚、首页、文章列表、标签、搜索、关于和文章正文在宽屏时左右对齐。

### 文章页

文章页不套 `.measure`，避免和三列网格各算一次留白。`app/(site)/posts/[slug]/page.module.css` 的 `.main` 去掉左右 padding，只留上下 padding。水平留白由 `components/table-of-contents.module.css` 的网格承担。

`.frame` 在所有宽度都用同一套网格，中间列与 `.measure` 同一条公式：

```css
.frame {
  display: grid;
  grid-template-columns:
    minmax(var(--gutter), 1fr)
    min(var(--measure), 100% - var(--gutter) * 2)
    minmax(var(--gutter), 1fr);
}

.column {
  grid-column: 2;
  width: auto;
  max-width: none;
  margin-inline: 0;
}
```

无目录时中间列仍是第 2 列。窄于 68rem 时侧列收缩到 `--gutter`，中间列不超过 `--measure`，效果与普通页的 `.measure` 相同。

目录：

- 小于 68rem：继续用标题和正文之间的 `<details>`，左侧 `.rail` 不显示。
- 68rem 起：隐藏 `<details>`，显示 `.rail`。宽度 `var(--toc)`，`justify-self: end`，贴着中间列；用 `padding-right: var(--toc-gap)` 留出与正文的间距。`position`、`top`、行号保持现在的粘性侧栏。

68rem 时每侧正好是 14rem，等于目录宽加间距。再宽时多出来的空间进两侧 `1fr`，正文保持居中。

文章标题在 768px 放大、上下篇在 640px 改成横排，这些留在 `page.module.css`，它们不是栏宽。

### 明确不动

- `app/admin/` 的侧栏、列表最大宽度、登录分栏、编辑器 1024px 双栏。
- 各组件里 640px 的排列：页脚横排、首页「最新」横排、列表缩略图宽度、导航里搜索二字。不要把这些收进 `tokens.css`。
- `utilities.css` 继续不放断点、颜色和任意宽高。

### 维护约定

写进 `docs/架构/项目架构.md` 新的一节「栏宽」，并在 `.cursor/rules/app.mdc` 的样式条里补上同一句约束：

- 公开站新页面的水平宽度只用 `measure`。模块样式里不再写 `max-width` 或 `padding-inline` 来收栏。
- 文章阅读栏只用 `table-of-contents.module.css` 的网格，网格中间列和 `.measure` 共用 `--measure` 与 `--gutter`。
- 改 `--measure`、`--toc`、`--toc-gap` 时，按 `tokens.css` 里的算式同步修改 68rem。
- 后台不引用这四个变量。

建议写入 `docs/架构/项目架构.md` 的段落：

```markdown
## 栏宽

公开站水平宽度由 `app/styles/tokens.css` 的 `--measure`（40rem）、`--gutter`、`--toc`、`--toc-gap` 决定。普通页用 `shared.css` 的 `.measure`：`min(40rem, 100% - 两侧留白)`，左右留白随视口在 1.25rem 到 2.5rem 之间变化。顶栏、页脚、首页、文章列表、标签、搜索、关于共用这一条，宽屏时文字栏对齐。

文章页用同一组变量做三列网格，中间列不超过 `--measure`。视口达到 68rem（正文栏 + 两侧的目录槽）时，左侧出现 12rem 的目录，并与正文隔 2rem。改这三个宽度变量时，要按同一算式改目录的媒体查询。

组件内部换行、缩略图横排仍用各自样式里的 640px，不进入栏宽变量。后台侧栏和编辑器双栏不用这套变量。
```

## 验收标准

- 宽屏下顶栏内容、首页、文章列表、标签、搜索、关于、文章正文的文字栏都是 40rem，左右位置一致
- 窄屏留白不小于 1.25rem，宽屏留白不超过 2.5rem，中间没有在 768px 突然改 padding 的规则
- 有目录的文章在 68rem 起显示左侧目录，目录宽 12rem，与正文相距 2rem，正文仍居中
- 无目录的文章在任意宽度都居中，且不超过 40rem
- 仓库里不再有 `--column`、`--column-wide`、`--reading`、`--toc-w`、`.shell`、`.page-wide`，文章网格不再写死 `760px` 或 `1280px`
- 后台页面的宽度和断点与改动前一致
- `docs/架构/项目架构.md` 和 `.cursor/rules/app.mdc` 写明新页面如何限宽，以及改栏宽变量时要同步改 68rem
