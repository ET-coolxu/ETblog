## 提示词正文

你是本仓库（ET blog）的实现助手。目标：实现个人博客第二版的专栏，不扩大到文档没写的能力。

## 本次需求

现在开始做 v2 专栏。行为以 `docs/requirements/v2.md` 为准。v2 没写到的，仍按 v1、后台工作台、访问记录里尚未被取代的条目。视觉、文案原句、文件和样式以 `docs/design/columns/spec.md` 为准，按该文第 2–7 节实现，不要另起一套尺寸。

栏目就是标签，不新增内容类型，不改 frontmatter，不改文章状态机。标签按原文精确匹配：折腾记录 `折腾记录`，AI 助手舰队 `舰队`，Bot 周报 `Bot周报`，资讯 `资讯`。一篇文章带多个标签时，可以同时出现在对应栏目里。站点不校验舰队文章的 Markdown 格式，只按普通 Markdown 渲染。

导航右侧改为：文章、专栏、标签、关于，细竖线后仍是搜索与主题。专栏链到 `/columns`。当前路径是 `/columns` 或 `/fleet` 时，「专栏」为选中态。`/posts/[slug]` 上仍是「文章」选中，包括带 `舰队` 标签的正文。无下拉，不收进汉堡菜单，不隐藏任何一项。窄屏只收间距，断点按设计稿 3.2：宽度小于 420px 导航间距 12px；小于 380px 品牌名字号降一档、间距再收。360px 宽顶栏四项、搜索、主题完整可见，页面无横向滚动。1440px 宽导航间距保持现有 `--space-7`。

`/columns`：

- 页头标题「专栏」，说明「舰队产出、作者审过的三类内容。」
- 依次三张卡片，再在页底放一块没有卡片框的资讯。
- 卡片标题后显示「· N 篇」。N 是该标签已发布总数。资讯不显示篇数。
- 简介用设计稿 4.1 的四句：折腾记录「从零搭东西的完整过程，踩坑和结论都写。」；AI 助手舰队「这支 bot 舰队里谁负责什么、彼此怎么接力，每月更新一次。」；Bot 周报「每周五一篇，从一周的 bot 使用经验里挑 3–5 条结论。」；资讯「AI 资讯速览，每几天一辑。」
- 折腾记录、Bot 周报、资讯各列最近 3 篇已发布文章，沿用 `listPublishedPosts` 的顺序（日期降序，同一天按 slug）。每篇有日期、标题、摘要；无摘要不渲染摘要。摘要一行省略。整行可点。「全部 →」用 `tagHref(tag)`。
- 舰队卡片不列文章。有已发布舰队文章时，显示该文日期和 bot 数，文案形如「更新于 2026-11-01 · 8 个 bot」；「查看舰队 →」链到 `/fleet`；右上链接文案是「往期 →」，链到 `tagHref("舰队")`。bot 数等于该文二级标题个数，用 `extractToc` 里 `depth === 2` 的条数。文章存在但没有二级标题时，显示 0 个 bot，链接仍在。
- 折腾记录或 Bot 周报没有已发布文章：「· 0 篇」，不显示「全部 →」，列表处写「还没有文章，第一篇在路上。」
- 没有已发布舰队文章：「· 0 篇」，不显示「往期 →」和「查看舰队 →」，写「舰队介绍还在整理中。」
- 资讯没有已发布文章：标题和简介仍在，不显示「全部 →」，空状态同一句「还没有文章，第一篇在路上。」
- 只含已发布。草稿和存档不出现。

`/fleet`：

- 渲染标签 `舰队` 里日期最新的一篇已发布文章。没有这篇时 HTTP 200，保留「← 专栏」和标题「AI 助手舰队」，不渲染日期行和页尾，正文处写「舰队介绍还在整理中。」，目录为空。
- 有文章时：正文和目录（h2）的渲染方式同 `/posts/[slug]`，阅读栏用现成的 `PostReadingFrame`，宽 52rem（832px）。标题固定为「AI 助手舰队」，不用文章自己的标题。页首是「← 专栏」、更新日期、bot 数，以及链到标签页的「舰队」。不显示阅读时长、封面、上一篇 / 下一篇。
- 页尾：「每月更新一次，旧版本留在往期里。」和「往期 →」（`tagHref("舰队")`）。
- 「角色」「协作对象」列表只在本页弱化，选择器按设计稿 5.5，不改 `app/styles/markdown.css`，也不改其他文章页的列表。
- 流程图是正文里的静态图片。舰队页只给「段落里单独一张图」限制最大宽度 27.5rem（440px）并居中。这条 `max-width` 只约束图片，正文栏宽仍只用 `PostReadingFrame`。浅灰底和细边框在图片里，站点不画图注，不另做深色版图片。
- 该文章的 `/posts/[slug]` 照常可访问，样式保持文章页原样。
- `/columns` 和 `/fleet` 不调用 `trackPageVisit`，不加新的访问记录类型，也不要复用 `{ kind: "post", slug }`。

首页「最新」追加排除：带 `HOME_EXCLUDE_TAGS` 中任一标签的文章不进入「最新」。未设置该环境变量时，默认排除 `Bot周报`、`资讯`、`舰队`。变量存在但去空白后为空，则不排除。排除放在截取 6 篇之前，并继续避开已经出现在精选里的文章；排除后不足 6 篇就少显示。精选不受排除影响。`/ 全部 N 篇` 和「当前显示 x / N 篇」里的 N 仍是全部已发布篇数。`/posts`、标签页、搜索、RSS 不排除这些文章。

发现与刷新：`sitemap.xml` 增加 `/columns`、`/fleet`。文章发布、更新、删除后，`revalidatePath` 带上这两条路径，不整站重建。

文档标题沿用根布局的 `%s · {SITE_NAME}`，两页的 metadata title 只写「专栏」和「AI 助手舰队」。`/fleet` 有文章时，description 用该文 summary。

预览站 `https://preview.coolxu.com/columns/` 只用来对照有数据时的版式和示例语气。正式实现以 v2 和设计稿为准。预览里这些不要带进正式站：页顶「原型：…」提示、标题后缀「（原型）」、`#` 占位链接、路径 `/columns/fleet/`、舰队卡片右上的「全部 →」。不要把预览里的示例文章写进仓库。

## 前置约束

- 先澄清假设，不臆造需求
- 改动范围最小化
- 遵循 `.cursor/rules`。产品行为以 v2 为准，结构以 `docs/架构/项目架构.md` 为准，样式分层以 `.cursor/rules/app.mdc` 为准
- 用户可见文案用简体中文
- 范围变化时，按 `.cursor/rules/iteration.mdc` 同步规则、架构说明和 README，不要把 `v2.md` 的文件名写进长期规则
- `.cursor/rules/project.mdc` 的「范围」补上本版仍不做、且尚未写入的禁令：导航下拉或二级菜单、按栏目 RSS、交互式流程图、正文 mermaid、后台栏目管理、栏目封面。评论、邮件订阅、多用户等已有禁令保持
- `docs/架构/项目架构.md` 写明公开导航含「专栏」，首页「最新」按可配置标签排除，以及 `/columns`、`/fleet` 不进入访问记录。README 首段的一句话现状加上专栏页和舰队页
- 本版不改：后台、发文接口、MCP、文章页、`/posts`、标签页、搜索、RSS、全局 `.markdown`、关于页。不做 `/columns/fleet`，也不做跳转到 `/fleet`
- Markdown 仍是唯一信源。不另存栏目数据库，不新增 frontmatter 字段
- slug、图片目录、`revalidatePath`、站名作者来自 `getSiteConfig()`、单管理员，这些工程约定不变
- 两页和首页一样 `export const dynamic = "force-dynamic"`
- 页面用 CSS Modules。不引入 Tailwind，不写行内样式。颜色、字号、间距只用 `tokens.css` 里的变量。深色模式只在 `tokens.css` 里重定义 `--card-line`，页面模块里不写 `.dark`
- `--card-line` 只给 `/columns` 卡片外框。浅色 `#d6d2c9`，深色等于 `--list-line`。卡片内部分隔线仍是 `--list-line`
- 公开页水平栏宽只用 `measure` 或 `PostReadingFrame`。模块里不用 `max-width` 或 `padding-inline` 收正文栏。设计稿 5.4 那条图片 `max-width` 除外
- `HOME_EXCLUDE_TAGS` 只作为运行时环境变量写入 `.env.example` 并加一行中文注释，不放进镜像构建参数
- 新增或改动的导出函数写中文 JSDoc
- 功能先合入 `test` 看构建，再生产只跟 `main` 的 GHCR 镜像。不要执行 `git commit` 或 `git push`

## 工作流程

1. 阅读 v2、设计稿、栏宽说明，以及导航、首页、文章页、`lib/posts.ts`、`lib/revalidate-posts.ts`、`app/sitemap.ts` 的现有写法，列出本次会改的文件
2. 信息不够时先追问，不靠猜测补需求
3. 需求文档已经写好。按 `.cursor/rules/iteration.mdc` 更新 `project.mdc`、架构说明和 README，然后写代码
4. 建议实现顺序：导航和首页排除、`/columns`、再 `/fleet`。一次做完
5. 实现后对照下面的验收项，并按设计稿第 9 节做视觉自查。用浏览器看本地开发服务器：有文章的 `/columns` 和 `/fleet`、两页空状态、首页排除、360 与 390 宽顶栏、深色卡片边框。缺真实专栏文章时，用本地未提交的文章验证，做完删掉，不要提交示例稿
6. 同一轮修掉因此出现的 lint 或框架报错
7. 若可沉淀通用经验，回复末尾用「提示词库建议」提出，确认后再改 `docs/agent/` 的类型模板

## 验收标准

- 顶栏顺序为文章、专栏、标签、关于。`/columns` 和 `/fleet` 上「专栏」选中，一篇舰队文章的 `/posts/[slug]` 上「文章」选中。无下拉。390px、360px 宽搜索和主题完整可见，360px 无横向滚动。1440px 导航间距与改前一致
- 带 `Bot周报`、`资讯` 或 `舰队` 的已发布文章不进首页「最新」；文章够的时候「最新」仍补到 6 篇，且不与精选重复。精选区不受排除影响。「全部 N 篇」和「当前显示 x / N 篇」的 N 仍是全部已发布篇数
- 修改 `HOME_EXCLUDE_TAGS` 后排除随之变化。显式留空时不排除。这些文章仍出现在 `/posts`、标签页、搜索、RSS
- `/columns` 三栏加资讯顺序正确。折腾记录、周报、资讯最多 3 篇，日期降序，「全部 →」能打开对应标签页。舰队卡片右上是「往期 →」，并显示更新日期和 bot 数，「查看舰队 →」打开 `/fleet`
- 卡片浅色边框为 `#d6d2c9`，深色与列表分隔线相同。资讯没有卡片框，只列标题，其「全部 →」不用 pine
- 某栏无已发布文章时篇数为 0，有对应中文空状态，且不显示该栏的「全部」「往期」「查看舰队」。草稿和存档不出现
- `/fleet` 显示最新一篇已发布 `舰队` 文章。新文章发布后不整站重建即可更新。正文栏宽与同一篇在 `/posts/[slug]` 下一致。标题是「AI 助手舰队」。「角色」「协作对象」只在本页弱化。其他文章的列表样式不变
- 没有已发布舰队文章时，`/fleet` 返回 200，显示「舰队介绍还在整理中。」
- 打开 `/columns` 或 `/fleet` 后，后台访问记录和文章 PV 不增加
- `sitemap.xml` 含 `/columns`、`/fleet`
- 后台、发文接口、文章页、`/posts`、标签页、搜索、RSS 的现有行为不变
